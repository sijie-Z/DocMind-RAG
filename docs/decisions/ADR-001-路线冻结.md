## 决策

### D1 · C3 会话与事件协议 = B 完整事件溯源（分阶段）

- 采用 append-only `session_events` 作为唯一真相 + 投影读模型；消息、运行状态、审批审计均为投影。
- 分阶段：事件存储与 seq → 投影/双写/回填/切读 → 前端消费（SSE id/Last-Event-ID、HITL）。
- **A+ 轻量增强降为回退方案**，仅在时间成为硬约束、或放弃 HITL/resume/审计、或多实例与事件量治理无法拍板时启用。
- 硬前置：chunk 合并策略（原始 token 不落库）、读切换开关、回填与回滚演练；首版保留 `ChatMessage` 作为回退真相至少一个版本。

### D2 · 产品定位 = A（企业文档问答 + 可干预 Agent 工作台）

- C（单机/小团队自托管）作为部署姿态；B（RAG 质量工程样板）作为质量纪律，不是主定位。
- 立即修两处核心高报：GraphRAG"知识图谱增强检索"（图谱未进 RAG 链）、"LLM 上下文压缩"（实为关键词句子抽取）。

### D3 · 管理员语义 = per-org RBAC + 显式平台管理员

- 取消 `role="admin"` → 全局 SysAdmin 的隐式映射（`permission_service.py:48`）。
- 平台级操作只认显式 `is_superuser` / `PlatformAdminScope`；组织管理员由组织成员角色判定，只能管理本组织。
- 需迁移脚本与审计；见 Wave 0/Wave 1。

### D4 · 多实例目标 = 按多实例/HA 就绪设计，首期可单实例部署

- 代码约束按多实例写：DB 租约（替代 Redis fail-open 互斥）、事务性 outbox、scheduler sharding、reaper 租约、通知与状态同事务。
- 该决策提高 C2 优先级；不允许把"单实例假设"写进新代码。

### D5 · 知识库语义 = 正式固化"组织=知识库"

- 不建 `knowledge_bases` 表；清理误导性命名（`list_knowledge_bases`、前端 `KnowledgeBase` 类型）。
- 仅在产品确认"一个组织多个知识库"后，另立 ADR 再做建表 + `documents.kb_id` + ES `_source.kb_id` + 全量重建索引。

### D6 · 密钥归属 = 平台级凭据先做

- 加密存储（专用 `CREDENTIAL_ENCRYPTION_KEY` 或现有密钥体系）+ `credential_ref`；API 只返回掩码/configured/source。
- 组织级/用户 BYOK 预留字段，不实现。
- `llm_config`（Redis，30 天 TTL、明文）导出后删除；`users.api_key` 迁移或删除。

### D7 · 事件粒度与 chunk = 任意事件边界 + 合并 delta

- SSE `id`/`Last-Event-ID` 支持任意事件边界。
- chunk 只持久化合并后的语义事件与最终消息；原始 token 不落库（写放大 gate）。

### D8 · Agent HITL = 完整历史 + 修复 chat 入口

- agent 页刷新恢复完整历史；chat 页 Agent 模式的 `approval_required` / `plan_approval_required` / `run_cancelled` 携带 `task_id` 与审批载荷，可操作可恢复。
- 过渡期如未就绪，可先禁用 chat Agent 模式并明确提示改用 /agent 页，但不得静默当作完成。

## 随决策一并采纳的默认项

| 项 | 决定 |
|---|---|
| llm_config | 导出后删除，不接线 |
| fork / request-header snapshot / unknown fail-closed | 事件模型预留，需求触发前不实现（header 先修 RequestIDMiddleware 语义） |
| 事件/审计保留 | 可配置保留策略；无合规结论前不写死天数 |
| OCR | 按定位 A：补齐扫描 PDF（pytesseract/pdf2image/tesseract/poppler）或明确收窄为"图片 OCR" |
| 提示词激活 | 每 `(org, category, scope)` 单 active，管理员事务维护；REST 列表修 `is_active` 过滤 |
| 运行对象 | 统一 `runs`（agent/chat/workflow/scheduled），随 C3 落地 |
| 知识库命名 | 组织=KB 的语义先收敛，0 DDL |

## 后果与风险

- B 工作量 5–7 模块 / 22–32 文件 / 3–5 迁移 + 回填 / 6–12k 生产 LOC / 4–8 周（估算，按上限更稳）。
- 主要风险：事件量写放大（chunk gate）、投影正确性（shadow read/双写）、回填保真、读切换回滚窗口。
- 回滚：切换前停双写即可回退；切读后用 feature flag 回退；不做首版破坏性迁移。

## 复核触发器（出现任一则重审 D1）

1. 时间变成硬约束（无法接受 4–8 周）；
2. 产品放弃 HITL/resume/审计中的任一项作为卖点；
3. 多实例与事件量治理无法拍板；
4. 投影等价测试无法达到零 diff。
