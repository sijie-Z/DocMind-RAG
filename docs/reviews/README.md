# 外部审阅记录（reviews）

本目录存放**向外部（另一个模型 / 另一个人）提问并记录答复的文档**。

## 为什么要留这个目录

这类问答的价值不在答案本身，而在**问题的组织方式**与**对方看不到代码时的盲区**。
`review-002` 就记录了一次典型翻车：提问文档没写"哪些已经做了"，
于是对方给了一堆关于**早已实现**的功能的建议 —— 这一条直接改进了 `review-003` 的写法。

## 现有文档

| 文件 | 内容 |
|---|---|
| `review-001-ci-strategy.md` | CI 投入策略（覆盖率、E2E、nightly、Dependabot） |
| `review-002-ci-followup.md` | 对 review-001 答复的逐条核实 + 新一轮提问。**含"答复方与代码现状不符"的逐条对照** |
| `review-003-docmind-harness-refactor.md` | DocMind 重构方向（检索底座 + harness 内核）。**§5 是"已完成/未完成基线"，§6 是作者自曝的错，§7 是不确定项** —— 这三节是为避免 review-002 的翻车而刻意加的 |

## 写法要求（给后来者）

1. **必须先写"已经做了什么"** —— 否则对方会就已有功能提建议（review-002 的教训）
2. **把关键证据贴在正文里** —— 对方看不到代码，只给结论等于让它猜
3. **单列自己的错误与不确定项** —— 让反驳有的放矢
4. **只问判断题，不问事实题** —— 事实自己能查；判断才是外部意见的价值
