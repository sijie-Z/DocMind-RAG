Agent 停下来等审批，是人工审批（HITL）机制在起作用：某个工具被判定为需要人工确认，任务在真正执行前被暂停。

## 谁会触发审批

- 审批模式为「所有工具调用审批」：任何工具调用都会暂停。
- 审批模式为「仅高危工具审批」（默认）：只有高风险工具会暂停。中央风险表中的高风险工具是 `execute_python`、`execute_sql`、`mcp_call`。
- 这三个工具由服务端强制保持关闭，界面开关无法启用（即使打开，服务端也会拒绝调用）；因此默认配置下通常不会出现审批。想验证审批流程，请切到「所有工具调用审批」，此时其他工具调用会触发审批卡片。
- 计划审批开启时，规划阶段也会暂停等待批准，这是另一套机制；当前没有界面开关，需服务端配置开启。

## 停在哪里、怎么继续

- 任务停在审批点时，Agent 工作台输入框上方会出现审批卡片；刷新页面后仍会恢复这张卡片。
- 点「批准」：任务恢复，该工具调用被允许执行；可以填写「改指令」作为人工指导注入后续步骤。
- 点「拒绝」：工具不执行，失败原因记录为 `approval_denied`，交给反思阶段处理。
- 同一组「工具 + 参数」的决定是粘性的，不会反复弹卡。

## 会一直等吗

默认审批超时为 0，表示无限等待，直到有人处理。若部署方配置了超时，超时会在读取/决策审批时判定（不是定时器），卡片失效并按失败（`approval_timeout`）处理。

## 注意

- 对话页的「深度分析」不展示审批卡片；需要处理审批请到 Agent 工作台。
- 任务取消后不会再有审批卡片；取消是协作式的，正在执行的工具会在下一个检查点收敛。

- `backend/app/api/v1/endpoints/agent.py`（审批接口、强制禁用工具合并）
- `frontend/src/components/agent/ApprovalCard.vue`
- `frontend/src/views/agent/index.vue`（恢复等待审批的现场）
