# 核验 golden set（D5/D6）

量化产品主张「逐条告诉你改了什么、证据在哪一句、且不猜」的确定性评测。
评测走与生产相同的路径：`semantic_chunker.split_text` → `Clause`（normalize +
clause 字段）→ `extract_*` → `align_item`，不调 LLM、不联网、不依赖 DB/ES。
模块自带离线环境默认值（`setdefault`，不覆盖真实环境），干净 clone 也可直接运行。

```bash
make review-eval           # 打三张表并与基线比对（CI 同款）
make review-eval-baseline  # 显式更新基线（评审可见的 PR 行为）
```

## 已知问题（下一批的输入）

1. v2 用例扩展（暂未覆盖）：付款条款经**两级以上**引用或引用环（A→B→C）；
   D10 只跟随一层，且要求引用与付款锚点同片段（不跨标点）；「双方约定按第四条
   付款」这类引用前无付款锚点、「依第四条」「按上述第四条」「详见合同第四条」
   等变体仍保守未识别（不产生错值）；引用目标不存在时降级
   `ambiguous/reference_unresolved`。引用区间超过 20 条时只跟端点（静默部分
   跟随）；`第4.2条`/section 编号、重复条号（取首个）、多条款同 chunk 会拉入
   兄弟条款期限，属已知顺序/粒度残余。
2. 被引用期限的动作守卫只检查**同一逗号片段**：`10个工作日内，完成发票开具`
   这类逗号隔开动作谓语的写法仍会被吸收；动作词表是有限黑名单（提供/寄送/
   送达/移交/报送/编制等未列）。根因是“定义 vs 顺延/动作”的语义区分，后续
   可改为结算类动词白名单或跨片段检查（需同步复核 D10 正例语义）。
3. 被引用条款整段文本进入付款项 `text_sha256`：其与付款无关的文字变化（如附件
   编号）会把付款项报 modified（保守误报）。
4. 验收项精度取舍：任何含「验收/发票/对账」字样的条款变更都会触发 acceptance
   modified（S1 修复后覆盖所有非例外含术语条款）；主证据会指向实际变化条款，
   属可解释的保守口径。
5. 口语歧义「一百五」按 105 解析（合同规范写法应为「一百零五」）；
   「一千二百/数十日」不抽取（不允许静默截取值）。
6. OCR 丢失分隔的紧贴标题（「第九条例外因不可抗力…」）不识别为例外条款：
   保守降级为正文（不误报 unchanged），后续可按词形补。
7. 起算事件剩余保守误报面：违约/赔偿/罚则标题与责任片段已排除（D12），但
   责任片段若不含罚则类词（仅「违约方应协商解决」）仍可能贡献起算；保密/
   交付类条款含付款词且提到 `合同生效` 时仍可能误触发起算。无标点连词切分
   只识别 并/且/及/以及 + 违约金/付款锚点形态（64 字内），其他连接词/距离
   仍是保守盲区；词内及只排除「涉及/及时」，波及/触及仍可能误命中。
   无逗号且 ≤120 字的正文前言仍可能被当标题；`_full_title` 对 >120 字极端
   标题返回 None；OCR 无换行/无空格 raw 下标题与正文粘连（既有）。反向后缀
   含「利息」仍按责任屏蔽（支付货款及利息 的起算保守丢失）。反向语序保留
   付款子句时，前导「合同生效后」片段不再屏蔽，可能多报一个起算事件
   （可辩口径）。词形变体 `合同签订并生效后`、`签订后生效` 仍未识别（N6）。
8. 更复杂的多动词/多期限结构仍按启发式归因：`10个工作日内验收，30天内支付`
   报 ambiguous（multiple_durations）；`30天内交付并付款` 保守不识别付款；
   验收条款里的 CN 月份可能因跨片段付款救援被误归付款（A-6）；
   `3个月15日` 被日期守卫保守拒绝（A-5）；`10个工作日内完成验收，甲方随后付款`
   在 payment_term 抽取仍报 identified 10（片段救援），10→15 会同时报 payment
   与 acceptance modified；期限后同片段无验收词时，后句/后分句的付款仍可能
   屏蔽前段验收期限（fallback 锚点跨句，base 既有）。属残余边界。
9. D15 R2 语义边界（有意为之，勿当 bug 修回）：
   - 违约责任/赔偿标题下的条款整条不参与付款与起算抽取；即使正文含明确
     付款期限也不抽取（罚则期限误报的代价大于漏报，正名用例
     `payment_liability_article_body_excluded` 锁定）。
   - 排除词中性化依赖 20 字窗口与结构标记（的/并/且/凭/所列/付款动词…）；
     超长定语（>20 字）仍可能保守否决付款；「社保的费用」按复合中心语
     处理、不予中性化。
   - 反向语序付款主体已可检出（甲方→乙方 报 payment modified）；正向语序
     主体在付款前缀内本就保留。主体变化同时改变其它文本时仍按文本哈希
     报 modified（保守口径）。
   - 反向语序中的比例/金额变化（70%→50%）会同时报 start/acceptance
     modified：这是 D14 之前的文本哈希保守口径（base 顺向同句式同样存在），
     本次登记不修。同理，反向责任句里的付款宾语/起算事件变化也会同时报
     start/acceptance modified（golden `payment_reverse_object_changed`、
     `start_reverse_conjunct_tax_event_changed` 已固化该口径）。

## D13 修复记录

- 同片段无标点连词（`支付货款并按日…违约金`）：只屏蔽连词（并/且/及/以及）
  后的责任子句，付款义务与起算事件保留；主体/否定变化可检出，违约金比例
  变化不污染四项。切分仅在连词前前缀含付款锚点**且不含违约金类词**时生效；
  前缀本身是责任子句（`支付违约金及赔偿损失`）时整片段屏蔽，否则比例/金额
  变化会重新污染四项（评审 B B1）。连词 lookahead 限定 64 字，避免长条文
  O(n²) 回溯。
- 标题边界：改为从 raw 文本提取完整标题（可跨行、含顿号）作为 hint，
  不再用固定 40 字窗口；正文冒号（「违约金：按日…」）不再被当标题，
  超长/多主题标题也不会被误判为非标题；`_heading_contains` 用完整标题，
  多主题标题（交付、验收与付款）的主证据不再漂移（评审 A 回退 2/3）。

  会让 raw hint 失配；`_heading_end` 按当前文本重新提取标题，标题含
  「逾期30日付款违约金」时验收/起算变化不再被责任片段屏蔽吞掉
  （评审 B B2）。
- golden 38→43 组（同片段无标点连词、无冒号混合标题+正文冒号、
  连词前责任前缀比例变化、超长/多主题标题、标题含期限下的验收变化）；

## 政策

- 基线文件包含指标 + 失败集合；任何变化（含提升）都必须显式更新基线并在 PR
  说明，pytest `tests/unit/test_review_golden.py` 会拦截未登记变化。
- 评测器敏感性有 canary 测试：四个核验项各写错一条 gold 都必须让指标下降，
  防止比较器被削弱后基线失效。
- 第二批替换为设计伙伴的真实脱敏合同（格式不变）；引用任何数字时注明样本量
  （当前 12 组）。
